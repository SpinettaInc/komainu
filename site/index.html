Why guardrails

How Komainu gets a written policy into daily use

An AI policy that sits in a document does not change what an assistant does. Komainu turns the policy into rules the assistant loads, and checks locally what can be checked.

Runs locally

The builder runs in your browser tab and the installer runs on your machine. Komainu has no service of its own.

Stores nothing

The site is static files. It has no database, no account and no form endpoint, and it uses no cookies or browser storage.

Labels every rule

Each rule is marked enforced, instructed or attested, so an instruction is never mistaken for a technical control.

Documents its limits

Most rules depend on the assistant following instructions. The limits section lists what Komainu does not do.

Features

What Komainu includes

Komainu covers engineering teams, other departments, leadership, IT administrators and the people who audit them.

builder.html

Full-width editor

Areas on the left, the rules you are editing in the middle, and the command and generated files on the right. All three update as you edit.

komainu import

Your own rules

Import rules from CSV or JSON. Common column names, separators and area names are recognized, and you see a preview before anything is added.

komainu-guard.mjs

Local enforcement hook

A Claude Code hook that blocks credentials, card numbers, your sensitive names, reads of secret files and dangerous commands before they leave the machine.

AGENTS.md

One source, every assistant

The same rules are written for Claude Code, Cursor, GitHub Copilot, Gemini CLI and Windsurf. Existing files are merged.

assistant-instructions/

Department packs

One paste-in block per department for teams that use a chat assistant and never open a repository: HR, sales, marketing, support, legal and finance.

acceptable-use-policy.md

Policy for people

A human-readable policy generated from the same configuration, with framework references and a checklist of the rules a person has to confirm.

komainu status

Drift check

Compares the installed files with komainu.json and exits with an error when they differ. Made for CI.

komainu check

Leak scan

Scans files, staged changes or standard input for credentials, personal data and your sensitive names. komainu redact replaces them with placeholders.

komainu mcp

MCP server

Six read-only tools for any MCP client: list the rules in force, check or redact text, decide where classified data may go, and preview a configuration.

skills/komainu-guardrails

Agent skill

Teaches a coding agent to read your policy documents locally, map each clause to a rule, and report the gaps before it installs anything.

komainu template

Policy templates

Download the rules for a role or an area as a CSV file, edit them in a spreadsheet and import the file. There are 11 role templates and one for each area. Browse the templates.

komainu quiz

Training quiz

A quiz made from the rules you selected, as one HTML file to share with your team. Or send a link that opens the quiz directly. People answer, see the reason behind each answer, and nothing is recorded.

Quickstart

Use it from the browser, the terminal or your agent

All five paths use the same catalog and write the same files. The CLI is one JavaScript file with no dependencies, and it makes no network requests.

Read komainu.mjs Checksums Offline builder 
# 1. build your configuration in the browser: {{BASE}}/builder.html
# 2. copy the command it gives you and run it in your repository
curl -fsSLo komainu.mjs {{BASE}}/komainu.mjs
node komainu.mjs apply eyJ2IjoxLCJkb21haW5zIjpbImNvcmUiLCJjb2RpbmciXX0

node komainu.mjs apply --dry-run     # preview without writing
node komainu.mjs status              # do the installed files still match?
# one file, no dependencies, needs Node.js 18 or newer
curl -fsSLo komainu.mjs {{BASE}}/komainu.mjs

node komainu.mjs init                # the wizard: answer a few questions
node komainu.mjs apply               # write the files from ./komainu.json
node komainu.mjs status              # exit 1 when files drift (use in CI)
node komainu.mjs check --staged      # scan staged files (use as pre-commit)
node komainu.mjs quiz > quiz.html     # a training quiz on your rules
echo "key=AKIA…" | node komainu.mjs redact
# key=[REDACTED_SECRET]
# start from a template: the rules for a role or an area, as CSV
node komainu.mjs template --list
node komainu.mjs template governance > policy.csv   # edit it, then import it

# or write your own file: only the "rule" column is required
rule,level,area,source
"Get approval from the People team before using AI on performance data.",must,HR,AI Policy 5.2
"Never paste customer contracts into a tool Legal has not approved.",must,Legal,Security Policy 4.1
"Prefer the internal style guide over the assistant's default tone.",should,Marketing,Brand Guide 2

# then
node komainu.mjs import rules.csv --dry-run
# Read 3 rule(s) from rules.csv (CSV).  1 Human resources  1 Legal & compliance  1 Marketing
node komainu.mjs import rules.csv && node komainu.mjs apply
# Claude Code
claude mcp add komainu -- node /absolute/path/to/komainu.mjs mcp

# any MCP client (.mcp.json)
{ "mcpServers": { "komainu": { "command": "node", "args": ["/absolute/path/to/komainu.mjs", "mcp"] } } }

# tools: guardrails_list  guardrails_check  guardrails_redact
#        guardrails_route guardrails_catalog guardrails_build
# read-only, stdio, speaks MCP 2026-07-28 and the earlier handshake
# install the skill for your coding agent
curl -fsSLo komainu.mjs {{BASE}}/komainu.mjs
node komainu.mjs skill install            # .claude/skills/komainu-guardrails
node komainu.mjs skill install --agents   # .agents/skills/ for other agents

# or without Node.js
mkdir -p .claude/skills
curl -fsSL {{BASE}}/skill/komainu-guardrails.tar.gz | tar -xz -C .claude/skills

# then ask your agent:
# "Build AI guardrails for our organization from our internal policies."

Data flow

What stays on your machine and what is sent

Stays on your machine

  • Everything you enter in the builder; the page cannot make network requests
  • Your policy documents and the rules files you import
  • Your sensitive names, which are kept out of every instruction file
  • What the hook blocks: credentials, card numbers and flagged commands

Sent to your AI provider

  • The rule text in your instruction files, when your assistant loads them
  • Your organization's name and contact role, if you entered them
  • Komainu itself sends nothing, to your provider or to anyone else

Limits

Known limits

Read these before relying on Komainu.

  • Most rules are instructed. An assistant that is told a rule usually follows it, and nothing checks that it did.
  • The enforcement hook works in Claude Code only. Other assistants receive the rules as instructions.
  • Detection is pattern-based. It catches common credential, card and bank-account formats and will miss others. For names and other personal data in prompts, use Veil, our Python library that replaces them with tokens before the text leaves your machine.
  • Komainu is not a runtime filter for an AI product you ship. Pair it with one if you build AI applications. Veil is the one we make for personal data.
  • The generated policy is a starting point and is not legal advice. Have it reviewed by your legal, security and privacy owners.
  • Sensitive names are stored in komainu.json and in the hook. Do not list a name there if the repository is shared with people who must not see it.

Build guardrails from your own policy

Komainu makes a policy harder to ignore but does not make it impossible to break. Read the limits before you rely on it.
