AI ガードレールビルダー · オープンソース · v0.1.0

AI ポリシーを、すべてのアシスタントが従うガードレールに

Komainu は、自社のポリシーをもとに、組織全体の AI ガードレールを作ります。ブラウザーでルールを選び、コマンドを 1 つコピーして、自分の端末で実行します。入力した内容は保存も送信もされません。

$ curl -fsSLo komainu.mjs {{BASE}}/komainu.mjs && node komainu.mjs init
ビルダーを開く ローカルで実行する
1 つのポリシー条項が Komainu を通る流れ · 厳格さ: 標準
1 · 自社のポリシー自社の文書

なぜ必要か

文書のポリシーを日々の業務に届ける方法

文書の中にあるだけの AI ポリシーは、アシスタントの動作を変えません。Komainu はポリシーをアシスタントが読み込むルールに変え、確認できるものはローカルで確認します。

ローカルで動く

ビルダーはブラウザーのタブで、インストーラーは自分の端末で動きます。Komainu 自身のサービスはありません。

何も保存しない

サイトは静的ファイルです。データベースも、アカウントも、フォームの送信先もなく、Cookie もブラウザーのストレージも使いません。

すべてのルールに区分を付ける

各ルールには「強制」「指示」「宣誓」のいずれかが付くため、指示が技術的な統制と取り違えられることはありません。

制限を明記する

ほとんどのルールは、アシスタントが指示に従うことを前提にしています。Komainu が行わないことは制限事項にまとめています。

仕組み

ポリシーからガードレールの導入まで 4 ステップ

ビルダー、CLI、MCP サーバー、エージェントスキルは、すべて同じルールカタログを使い、同じファイルを書き出します。

01

選ぶ

テンプレートから始めて、AI を使うチームを選びます。ルールのオンとオフを切り替え、厳格さを決めます。

18 領域 → 185 ルール
02

独自のルールを加える

ポリシーテンプレートをダウンロードし、表計算ソフトで編集してインポートします。または、エージェントスキルにポリシー文書を条項ごとに対応付けさせます。

rules.csv → 独自のルール
03

コマンドを 1 つコピーする

選んだ内容はコマンドそのものに含まれています。オフラインインストーラーと、コーディングエージェント用のプロンプトも用意されます。

komainu.mjs apply eyJ2Ijox…
04

ローカルに導入する

コマンドは、各アシスタントが読むルールファイル、ローカルの強制フック、人が読むためのポリシー文書を書き出します。

AGENTS.md + komainu-guard.mjs

機能

Komainu に含まれるもの

Komainu は、エンジニアリングチーム、その他の部門、経営層、IT 管理者、そして監査を行う人までを対象にしています。

builder.html

全幅のエディター

左に領域、中央に編集中のルール、右にコマンドと生成されるファイル。編集するたびに 3 つすべてが更新されます。

komainu import

独自のルール

CSV または JSON からルールをインポートできます。一般的な列名、区切り文字、領域名を認識し、追加する前にプレビューを表示します。

komainu-guard.mjs

ローカルの強制フック

認証情報、カード番号、機密名称、秘密ファイルの読み取り、危険なコマンドを、端末から出る前にブロックする Claude Code のフックです。

AGENTS.md

1 つの定義をすべてのアシスタントへ

同じルールを Claude Code、Cursor、GitHub Copilot、Gemini CLI、Windsurf 向けに書き出します。既存のファイルにはマージします。

assistant-instructions/

部門別パック

リポジトリを開くことのない、チャットアシスタントを使うチームのために、部門ごとに貼り付け用のブロックを用意します: 人事、営業、マーケティング、サポート、法務、財務。

acceptable-use-policy.md

人が読むためのポリシー

同じ設定から生成される、人が読めるポリシーです。フレームワークへの参照と、人が確認する必要のあるルールのチェックリストが付きます。

komainu status

ずれの検出

導入済みのファイルを komainu.json と比較し、違いがあればエラーで終了します。CI での利用を想定しています。

komainu check

漏えいスキャン

ファイル、ステージ済みの変更、標準入力を対象に、認証情報、個人データ、機密名称を検出します。komainu redact はそれらをプレースホルダーに置き換えます。

komainu mcp

MCP サーバー

どの MCP クライアントでも使える、読み取り専用の 6 つのツールです: 有効なルールの一覧、テキストの検査と伏せ字化、分類されたデータの送り先の判断、設定のプレビュー。

skills/komainu-guardrails

エージェントスキル

コーディングエージェントに、ポリシー文書をローカルで読み、各条項をルールに対応付け、導入の前に不足を報告する手順を教えます。

komainu template

ポリシーテンプレート

役割または領域ごとのルールを CSV ファイルでダウンロードし、表計算ソフトで編集してインポートできます。役割テンプレートが 11 種類と、領域ごとのテンプレートがあります。テンプレートを見る。

komainu quiz

研修クイズ

選んだルールから作るクイズを、チームに共有できる 1 つの HTML ファイルとして書き出します。クイズを直接開くリンクを送ることもできます。回答すると各問の理由が表示され、何も記録されません。

厳格さ

厳格さのレベル

レベルによって、既定でオンになるルールとフックの動作が決まります。

strict185 ルール

すべてのルールがオン。フックはブロックします。規制業種や高リスク環境向け。

balanced150 ルール · 既定

必須事項と良い慣行。フックは明確な違反をブロックします。

advisory70 ルール

必須事項のみ。フックは確認を求め、ブロックはしません。

データの流れ

端末に残るものと、送信されるもの

端末に残るもの

  • ビルダーに入力したすべての内容。このページはネットワークリクエストを送れません
  • ポリシー文書と、インポートするルールファイル
  • 機密名称。どの指示ファイルにも書き込まれません
  • フックがブロックするもの: 認証情報、カード番号、警告対象のコマンド

AI プロバイダーに送信されるもの

  • 指示ファイルにあるルールの文言 (アシスタントが読み込むとき)
  • 組織の名称と担当の役割 (入力した場合)
  • Komainu 自身は、プロバイダーにも他の誰にも、何も送信しません

数値はこのビルドのカタログから取得しています。ルールの文言は Komainu 独自のもので、規制当局や標準化団体の審査は受けていません。

制限事項

既知の制限

Komainu に頼る前にお読みください。

  • ほとんどのルールは「指示」です。ルールを伝えられたアシスタントは通常それに従いますが、従ったことを確認する仕組みはありません。
  • 強制フックが動作するのは Claude Code だけです。他のアシスタントはルールを指示として受け取ります。
  • 検出はパターンに基づきます。一般的な認証情報、カード、銀行口座の形式は検出しますが、それ以外は見逃します。プロンプト内の氏名やその他の個人データには、テキストが端末を出る前にトークンへ置き換える当社の Python ライブラリ Veil を使ってください。
  • Komainu は、提供する AI プロダクトのための実行時フィルターではありません。AI アプリケーションを開発する場合は、実行時フィルターと組み合わせてください。個人データ向けには当社の Veil があります。
  • 生成されるポリシーは出発点であり、法的助言ではありません。法務、セキュリティ、プライバシーの担当者によるレビューを受けてください。
  • 機密名称は komainu.json とフックに保存されます。見せてはならない人とリポジトリを共有している場合は、そこに名称を登録しないでください。

自社のポリシーからガードレールを作る

Komainu はポリシーを無視しにくくしますが、破ることを不可能にするわけではありません。頼る前に制限事項をお読みください。
